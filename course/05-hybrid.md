# 5단계 — 키워드 검색 만들고 임베딩과 섞기

## 왜 하나요

3단계에서 임베딩은 바꿔 말한 질문에 강하고, 숫자·코드에는 약했어요. 키워드 검색은 그 반대예요. 둘의 순위를 섞으면 양쪽 장점을 다 얻을지 시험지로 확인해요.

| 말 | 쉬운 뜻 |
|---|---|
| BM25 | 검색 단어가 그 문서에 많이 나오고, 다른 문서에는 드물수록 점수를 높게 주는 키워드 검색 |
| RRF (순위 섞기) | 문서마다 각 검색에서의 순위 r 로 `1/(k + r)` 을 더해 다시 줄 세우기. 점수가 아니라 순위만 써서 성질이 다른 두 검색을 섞기 쉬워요 |

먼저 짐작해서 적어요: "섞으면 바꿔 말함 @5 가 임베딩만 썼을 때보다 오를까, 내릴까?"

## 만들 것 1: `keyword_search.py`

1회차는 원래 쓰던 키워드 검색 도구를 썼어요. 재수강에서는 직접 만들어요.

```text
5단계 준비로 키워드 검색기 keyword_search.py 를 만들어줘.
- 실행: python3 keyword_search.py --index private/index [--top 50] [--json] 단어1 단어2 …
- 자료: 색인 폴더의 chunks.jsonl 만 읽어 (임베딩은 안 써). 같은 path 의 조각 text 를 이어 붙여 문서 1편으로 봐
- 토큰 나누기: 소문자로 바꾸고 글자·숫자 덩어리로 잘라. 한글 덩어리는 조사("임베딩은", "임베딩을") 때문에 안 맞으니까
  두 글자씩 겹쳐 자른 조각(바이그램: "임베딩은" → "임베", "베딩", "딩은")도 같이 넣어
- 점수: BM25 (k1=1.2, b=0.75). 검색 단어도 같은 방법으로 토큰을 나눠
- 출력: --json 이면 {"hits": [{"path": 문서 경로, "score": 점수}, …]} 를 점수 순으로 --top 개,
  아니면 사람이 읽기 좋은 목록
- 단어가 하나도 안 맞는 문서는 결과에서 빼
```

```sh
python3 keyword_search.py --index private/index 임베딩 정규화
```

- 1회차 도구는 "모든 단어가 다 들어간 문서만" 찾는 방식이라 결과가 달라질 수 있어요. 그 차이도 관찰 거리예요

## 만들 것 2: `step5_hybrid.py`

```text
5단계 섞어 찾기 채점 step5_hybrid.py 를 만들어줘.
- 실행: python3 step5_hybrid.py <시험지.json> <결과.json> --keyword-cmd "python3 keyword_search.py --index private/index --json"
        [--index private/index] [--rrf-k 60] [--depth 50] [--kw-weight 1.0]
- 키워드 순위: --keyword-cmd 뒤에 문항의 keywords_a 단어들을 붙여 실행하고, 출력 JSON 의 hits[].path 순서 (상위 depth 개)
- 임베딩 순위: step4_eval.py 의 doc_ranking 을 import 해서 상위 depth 개
- exclude_prefix 가 있으면 두 순위 모두에서 빼
- 섞기(RRF): 문서마다 각 순위 r 에 대해 가중치/(k + r) 를 더해 큰 순. 키워드 가중치 = --kw-weight, 임베딩 가중치 = 1.0
  한쪽 순위에만 나온 문서도 점수를 받아
- 출력: 문항마다 "키워드 순위 / 임베딩 순위 / 섞은 순위" (depth 밖은 -),
  끝에 group 별로 세 방식 각각의 recall@1·recall@5
```

## 직접 실행

```sh
python3 step5_hybrid.py private/eval/testset.json results/step5-k60.json \
  --keyword-cmd "python3 keyword_search.py --index private/index --json"
```

## 확인하기 (`내기록.md` 에 적기)

| 방식 | 1회차 단어 겹침 @1 / @5 | 1회차 바꿔 말함 @1 / @5 | 내 단어 겹침 | 내 바꿔 말함 |
|---|---|---|---|---|
| 키워드만 | 6 / 10 | 0 / 0 | | |
| 임베딩만 | 8 / 10 | 3 / 6 | | |
| 섞기 k=60 | 7 / 10 | 1 / 4 | | |

- 섞기가 나빠진 문항을 하나 골라 "키워드 / 임베딩 / 섞기" 순위를 보고 왜 그랬는지 적어요

## 코드에서 꼭 읽을 곳

1. `rrf` 함수의 `가중치 / (k + r)` — 두 목록에 **함께** 나온 문서가 왜 위로 올라가나
2. BM25 에서 "다른 문서에 드문 단어일수록 점수가 높다" 부분 (IDF) — 흔한 단어가 왜 힘이 약한가
3. 한글 바이그램 — 이게 없으면 "임베딩은"으로 "임베딩"을 못 찾는 이유

## 고쳐 보기

| 바꿀 것 | 짐작 먼저 | 확인 |
|---|---|---|
| `--rrf-k 10` | 1위의 힘이 세지면 무엇이 달라질까? | 바꿔 말함 @5 |
| `--kw-weight 0.5` | 키워드를 덜 믿으면 나아질까? | 바꿔 말함 @5 |
| 한글 바이그램 끄기 | 키워드만 점수가 어떻게 될까? | 키워드만 @5 |

- 20문항에 맞춰 k·가중치를 고르면 이 시험지에만 맞는 값이 돼요(과적합). 고르지 말고 결과만 기록해요
