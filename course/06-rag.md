# 6단계 — 찾은 조각으로 답하게 하고 답 채점하기

## 왜 하나요

드디어 RAG 전체를 이어요: 질문 → 조각 5개 찾기 → 조각에 번호를 붙여 모델에 같이 주기 → 답. 그리고 답을 채점해요. RAG 가 틀리는 이유는 둘 중 하나예요 — **찾기를 못 했거나, 찾고도 답을 잘못 했거나.** 그래서 채점을 4칸으로 나눠요.

| | 거절함 ("자료에 없어요") | 답함 |
|---|---|---|
| 찾기 성공 (정답 조각이 5개 안에) | 잃은 정답 — 아까워요 | 좋은 경우 (답이 맞는지는 눈으로 확인) |
| 찾기 실패 | 안전한 실패 | 위험할 수 있어요 — 엉뚱한 조각으로 자신 있게 틀림 |

먼저 짐작해서 적어요: "찾기 실패한 문항에서 모델은 거절할까, 엉뚱한 조각으로 답할까?"

## 준비: 질문 추가

시험지 20문항에 2개를 더해 `private/eval/extra.json` 에 써요.

```json
{
  "exclude_prefix": null,
  "items": [
    {"id": "X1", "question": "<1단계 '내 문서에만 있는 사실' 질문>", "gold_paths": ["<그 답이 적힌 문서>"]},
    {"id": "N1", "question": "<내 문서 폴더에 답이 없는데, 비슷한 주제 문서는 있는 질문>", "gold_paths": []}
  ]
}
```

- `gold_paths` 가 빈 목록 = 답이 없는 질문. 거절이 정답이에요

## AI 에게 줄 말

처음에는 거절 판정을 **정확한 문구로만** 해요. 모델이 말을 바꿔서 거절하면 놓칠 텐데, 그걸 직접 보는 게 이 단계의 공부예요.

```text
6단계 찾기+답하기 스크립트 step6_rag.py 를 만들어줘.
- 실행: python3 step6_rag.py <결과.json> <시험지.json> [<시험지.json> …] [--model qwen3.5:4b] [-k 5] [--index private/index]
- 시험지 형식은 4단계와 같아. gold_paths 가 빈 목록이면 "문서 폴더에 답이 없는 질문"이야
- 진행 순서:
  1) 모든 문항의 조각 k 개를 먼저 다 찾아 (step3_search.py 의 load_index·embed 를 import)
  2) 임베딩 모델을 메모리에서 내려 (/api/embed 에 model, input "", keep_alive 0) — 두 모델이 동시에 메모리에 오르지 않게
  3) 문항마다 답하기
- 답하기 지시(system): "너는 문서 도우미야. 한국어로만 답해. 아래 [자료]만 근거로 답하고, 근거가 된 자료 번호를
  문장 끝에 [1]처럼 붙여. 자료로 답할 수 없으면 '자료에 없어요'라고만 답해. 3문장 이내로 답해."
- 사용자 메시지: "[자료]\n[1] 출처: 경로 > 헤딩\n조각 text\n\n[2] …\n\n[질문]\n질문"
- 호출: /api/chat, think false, temperature 0, num_ctx 12288, 타임아웃 240초.
  타임아웃이 나면 그때까지 결과를 저장하고 멈춰 (메모리 부족 신호)
- 거절 판정 is_refusal(답): 답에 '자료에 없어요' 가 들어 있으면 거절. 함수로 분리해 (나중에 고치고, 7단계에서 import)
- 칸: 정답 조각이 k 개 안에 있나(찾기 성공/실패) × 거절했나(거절/답함).
  gold_paths 가 비면 "답 없는 질문 · 거절" 또는 "답 없는 질문 · 답함"
- 인용: 답 속 [n] 번호 목록, 그중 정답 조각 번호가 있나
- 결과 JSON 은 문항마다 id, question, cell, gold_in_context(정답 조각 번호 목록), cited, cited_gold, answer,
  context("path:line" 목록), prompt_tokens, answer_tokens, seconds
- 화면: 문항마다 칸·정답 조각 위치·인용·토큰·초, 답 앞 220자. 끝에 칸별 개수
```

## 직접 실행

## 손으로 채점하기 (가장 중요)

자동 칸 나누기를 믿기 전에, 22문항 답을 하나씩 읽고 표를 채워요. AI 에게 표 틀만 만들어 달라고 해도 돼요.

| id | 자동 칸 | 실제로 거절했나 | 답이 맞나 | 위험한 답? (엉뚱한 근거로 자신 있게 틀림) |
|---|---|---|---|---|

- 자동 판정과 다르게 본 거절이 있으면 → `is_refusal` 을 고칠 차례예요 (아래 고쳐 보기)
- 답에 나온 숫자가 붙여 준 조각 안에 있는지도 확인해요. 조각에 없는 숫자 = 지어낸 숫자

## 코드에서 꼭 읽을 곳

1. system 지시문 — 근거 번호 `[n]` 과 "자료에 없어요"를 시키는 두 문장
2. 조각에 `[1] 출처: 경로 > 헤딩` 을 붙이는 부분 — 모델이 출처를 구분하게 하는 방법
3. `is_refusal` — 모델이 지시 문구를 그대로 쓰지 않으면 어떻게 되나

## 고쳐 보기

| 바꿀 것 | 짐작 먼저 | 확인 |
|---|---|---|
| `is_refusal` 넓히기: 손 채점에서 놓친 거절 문장을 AI 에게 보여 주고 "이런 말도 거절로 보되, 근거를 들어 답한 답은 거절로 보지 않게 고쳐 줘" | 칸 개수가 어떻게 바뀔까? | 다시 실행한 칸 개수와 손 채점이 같아지나 |
| `-k 3`, `-k 10` | 위험한 답이 늘까, 줄까? | 칸 개수·시간 |
| system 에서 "[1]처럼 붙여" 빼기 | 답이 더 자유로워질까? 위험해질까? | 위험한 답 수 |

- 1회차 정답지의 거절 판정 = "첫 문장에 `자료 … 없어요/없습니다/않습니다/부족` 이 있고, 답이 160자 미만이거나 마지막 문장도 그러면 거절". 두 번 넓혀서 이 모양이 됐어요
