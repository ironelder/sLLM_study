# 8단계 — 더 큰 모델(9B)로 같은 비교 (선택)

## 왜 하나요

지금까지의 실패가 **모델이 작아서**인지, **방법이 부족해서**인지 가르려면 같은 질문·같은 조각에 모델만 바꿔 보면 돼요. 코드는 안 바꾸고 `--model` 만 바꿔요.

먼저 짐작해서 적어요: "9B 는 4B 보다 위험한 답이 줄까? 문서 없이 물으면 덜 지어낼까?"

## 하기 전에: 메모리 확인

| 메모리 | 할까? |
|---|---|
| 8GB | 하지 않아요 |
| 16GB | 다른 앱을 거의 다 끄고 해요. 1회차는 스왑(메모리가 모자라 디스크로 밀어낸 양)이 21GB 까지 찼고, AI 도구가 메모리 부족으로 실행 하나를 강제로 멈췄어요 |
| 32GB 이상 | 해요 |

```sh
memory_pressure | tail -1       # free percentage 가 높을수록 여유
sysctl vm.swapusage             # used 가 크면 이미 빠듯
```

- 9B 실행은 **내 터미널에서 직접** 해요. AI 도구 안에서 백그라운드로 돌리면, 메모리가 모자랄 때 도구가 그 실행을 끊을 수 있어요

## 직접 실행

```sh
ollama pull qwen3.5:9b                                   # 약 7.6GB
python3 step1_chat.py qwen3.5:9b
python3 step2_attach.py qwen3.5:9b
python3 step6_rag.py results/step8-9b.json private/eval/testset.json private/eval/extra.json --model qwen3.5:9b
python3 step6_rag.py results/step8-9b-label.json private/eval/testset.json private/eval/extra.json --model qwen3.5:9b --index private/index-proj
python3 compare_runs.py 4B=results/step6.json 9B=results/step8-9b.json 9B이름표=results/step8-9b-label.json --no-answer-ids N1
```

- 첫 질문은 모델을 올리느라 오래 걸려요. 1회차는 메모리가 빠듯할 때 글자 9개를 쓰는 데 160초가 걸린 적도 있어요
- 6단계 코드가 "찾기 먼저 → 임베딩 모델 내리기 → 답하기" 순서인 이유가 여기 있어요. 두 모델이 같이 올라가면 16GB 가 모자라요

끝나면 지워요.

```sh
ollama rm qwen3.5:9b
ollama list            # qwen3.5:4b, bge-m3 만 남았나
```

## 확인하기 (`내기록.md` 에 적기)

| 항목 | 1회차 4B | 1회차 9B | 내 4B | 내 9B |
|---|---|---|---|---|
| 답 쓰는 속도 (초당 토큰) | 약 40 | 22~25 | | |
| 문서 없이 내 문서 질문 (1단계) | 엉뚱하게 지어냄 | **더 그럴듯하게** 지어냄 | | |
| 바꿔 말한 질문 + 정답 문서 (2단계) | 판단 보류 | 표현 차이를 이어서 답함 | | |
| 위험한 답 (6단계) | 2 | **0** | | |
| 잃은 정답 (6단계) | 0 | 0 (이름표 붙이면 1) | | |
| 답 없는 질문 N1 | 다른 대상 조각으로 오답 | "이 자료는 다른 프로젝트라 관련 없다"며 거절 | | |
| 문항당 시간 | 7.3초 | 27.5초 | | |

## 생각해 볼 것

- 큰 모델이 더 그럴듯하게 지어내면, 문서 없이 쓸 때는 오히려 더 위험해요. 왜 그런지 적어 봐요
- 4B 에 이름표 + 확인 지시로 얻은 효과를 9B 는 그냥 얻었어요. 그러면 7단계 장치는 9B 에 필요할까?
- 정확도 vs 속도·메모리. 내 기기에서는 어느 쪽을 고를지

## 1회차와 비교

- 1회차 정리: [`../notes/step8.md`](../notes/step8.md)
- 1회차 결론: 모델 크기가 가장 큰 차이를 만들었어요(위험한 답 2 → 0). 대신 4배 가까이 느리고 16GB 에서는 메모리가 빠듯했어요. 개선 장치(이름표)는 모델마다 효과가 달라서 모델을 바꿀 때마다 다시 재야 해요
- 1회차의 9B "이름표 + 확인 지시" 실행은 메모리 부족으로 22문항 중 18문항에서 멈췄어요 (그때까지 위험한 답 0)
