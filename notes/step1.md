# 1단계 정리 — 문서 없이 sLLM 에 질문하기 (2026-11-11)

## 환경

- MacBook Pro M1 Pro, RAM 16GB
- Ollama v0.40.16, 모델 `qwen3.5:4b`, 생각 블록 끔(`think: false`), temperature 0

## 측정

| 항목 | 값 | 뜻 |
|---|---|---|
| 처음 켜는 시간 | 13.3초 | 첫 질문 때 모델을 메모리에 올리는 시간. 이후 5분은 올려 둔 채라 0초 |
| 답 쓰는 속도 | 초당 약 40토큰 | 3줄 답(84토큰) 2.2초, 긴 답(541토큰) 13.5초 |

| 한 번에 읽는 양 | 4096토큰(기본값) | 문서를 붙이려면 `num_ctx` 를 늘려야 함 |

## 관찰

| 질문 종류 | 결과 |
|---|---|
| 공개 자료에 많은 일반 지식(안드로이드 ViewModel) | 얕지만 대체로 맞음. 한국어 문장 자연스러움 |
| 회사 내부에서만 쓰는 오류 코드 | 없는 오류 형식·엉뚱한 해석을 지어내고 "공식 코드가 아니다"라고 단정 |
| 회사 내부 규칙(저장소 PR 브랜치) | 맞혔지만 "대부분 저장소가 그렇다"는 일반 관례로 찍은 답. 쓰는 서비스(GitHub/Bitbucket)도 틀림 |

직접 대화(`ollama run`, 한 대화창에서 이어서)에서 본 것:

- "모르면 모른다고 답해" 지시는 먹힘. 다만 거절하면서도 세부를 지어냄
- 앞에서 한 지시가 같은 대화의 다음 질문까지 이어짐(대화 기록 전체가 다음 입력에 들어가기 때문)
- 짧게 답하라고 해도 긴 한 문장, 중국어 단어가 섞임(작은 다국어 모델의 언어 섞임)
- 시계가 없는데 "기쁜 아침"이라고 시간을 지어냄
- 붙인 글 없이 "위 글 요약"이라고 하면 앞 대화를 글로 보고 복사함

## 배운 것

- 작은 모델은 내가 가진 문서의 내용을 모르고, 모르는 걸 그럴듯하게 지어냄 → RAG(답하기 전에 문서를 찾아 붙이기)가 필요한 이유
- 문서 없이 맞힌 답은 맞았는지 찍었는지 구분할 수 없음
- 실험할 때는 질문마다 새 대화로 보내야 앞 지시가 섞이지 않음

## 2단계에 반영

- 질문마다 새 대화, 시스템 지시 "한국어로만·문서에 없으면 모른다고"
- 문서를 붙일 수 있게 `num_ctx` 확대
