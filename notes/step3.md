# 3단계 정리 — 문서 폴더 조각내기·임베딩으로 찾기 (2026-11-11)

## 방법

- 대상: 개인 문서 폴더의 md 474편 (`step3_index.py`)
- 조각내기: 헤딩(`#`) 단위로 자르고, 1200자 넘는 절은 빈 줄 단위 문단으로 나눔. 조각 앞에 "문서 제목·키워드·절 경로"를 붙여 조각만 떼어 봐도 무엇에 대한 내용인지 남게 함
- 임베딩: `bge-m3` (1024차원), 순수 파이썬으로 저장·코사인 계산 (numpy 없이)
- 찾기: 질문을 같은 모델로 임베딩 → 6,855개 조각과 비교 → 가까운 5개 (`step3_search.py`)
- 비교: 기존 키워드(BM25) 검색에 같은 질문을 단어로 쪼개 넣음(모든 단어가 들어간 문서만 찾는 AND)

## 측정

| 항목 | 값 |
|---|---|
| 조각 수 | 6,855개 (중앙값 647자, 90%가 1,309자 이하) |
| 색인 만드는 시간 | 689초 (초당 약 10개, M1 Pro GPU) |
| 색인 크기 | 벡터 28MB + 조각 원문 9MB |
| 질문 1개 찾는 시간 | 0.3~0.4초 |

## 결과

| 질문 종류 | 키워드 검색 | 임베딩 검색 |
|---|---|---|
| 회사 오류 코드가 든 질문 (문장 그대로) | 실패 | 실패 — 질문 속 흔한 단어(회사 이름)에 끌려 엉뚱한 문서 |
| 증상을 일상어로 바꿔 말한 질문 | 실패 | **성공** — 정답 보고서가 1·2·4·5위 |
| 짧은 불만형 질문 ("로그인이 자꾸 풀려요") | 3위에 관련 문서 | 3위에 같은 관련 문서 |
| 문서 폴더에 없는 규칙 질문 | 실패 | 실패 |
| 오류 코드 숫자 한 단어 | **성공** — 정답 보고서 포함 4건 | 실패 쪽 — 숫자가 많은 엉뚱한 목록 문서가 1·2위, 정답은 5위 |

- 맞은 결과 1위 점수 0.655, 틀린 결과 1위 점수 0.640 → 점수만으로는 맞고 틀림을 가를 수 없음

## 배운 것

- 임베딩은 뜻으로 찾는다 → 단어가 하나도 안 겹치는 바꿔 말한 질문에 강함
- 임베딩은 숫자·코드·고유명사에 약하다 → 정확한 식별자는 키워드 검색이 이김
- 둘이 잘하는 곳이 다르다 → 섞어 찾기(5단계)를 할 이유
- 문서 폴더에 없는 지식은 어떤 검색으로도 못 찾는다
- 질문 몇 개로는 판단이 흔들린다 → 4단계에서 시험지로 숫자를 잰다

## 4단계에 반영

- 기존 시험지로 recall@5 를 키워드 검색과 임베딩 검색 각각 채점
