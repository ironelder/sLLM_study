# 6단계 정리 — 찾기부터 답하기까지 한 번에 (2026-11-11)

## 방법

- 질문 → 임베딩으로 조각 5개 찾기 → 조각에 `[1]`~`[5]` 번호와 출처를 붙여 `qwen3.5:4b` 에 전달 → 답 (`step6_rag.py`)
- 지시: "자료만 근거로, 문장 끝에 근거 번호 [n], 답할 수 없으면 '자료에 없어요', 3문장 이내"
- 질문 22개: 시험지 20 + 오류 코드 문장 질문 1 + 문서 폴더에 답이 없는 질문 1 (거절이 정답)
- 채점은 RAG 의 실패를 둘로 나누는 4칸: **찾기**가 성공했나(정답 조각이 5개 안에 있나) × **답했나/거절했나**

## 결과

| 칸 | 개수 | 뜻 |
|---|---|---|
| 찾기 성공 · 답함 | 15 | 좋은 경우. 15개 중 14개가 정답 조각 번호를 인용 |
| 찾기 실패 · 거절 | 4 | 안전한 실패 — 못 찾았고, 지어내지도 않음 |
| 찾기 실패 · 답함 | 2 | 1개는 엉뚱한 조각으로 틀린 답(위험), 1개는 같은 주제 이웃 문서로 쓸 만한 답 |
| 답이 없는 질문 · 답함 | 1 | **가장 위험** — 다른 프로젝트 문서의 브랜치 이름을 가져와 그럴듯하게 틀림 |

측정
| 항목 | 값 |
|---|---|
| 질문 1개 처리 | 중앙값 7.3초 (5.5~13.2초) |
| 입력(조각 5개 + 질문) | 중앙값 2,344토큰 |
| 답 길이 | 중앙값 58토큰 |

숫자 근거 대조
- 답에 나온 숫자·퍼센트·버전 21개는 전부 붙여 준 조각 안에 있었음 → 숫자를 새로 지어낸 경우 0
- 하지만 조각 안의 숫자를 **엉뚱한 질문에 갖다 붙인** 경우(위험 2건)는 이 대조로 못 잡음

## 1단계와 비교 (같은 회사 질문)

| 질문 | 1단계: 문서 없음 | 6단계: 찾아서 붙임 |
|---|---|---|
| 오류 코드가 나오면 로그인이 풀리나 | 없는 오류 형식을 지어냄 | 찾기 실패 → "자료에 없습니다" (안전) |
| 저장소 PR 브랜치 | 일반 관례로 찍어 맞힘 | 엉뚱한 조각의 브랜치 이름으로 오답 |
| 증상을 바꿔 말한 질문 | — | 정답 + 근거 번호 |

## 배운 것

- "자료에 없으면 모른다" 지시 덕분에 찾기 실패 6건 중 4건은 안전하게 거절했다
- 가장 위험한 실패는 **찾은 조각이 질문과 비슷하지만 다른 대상**일 때다. 모델은 조각에 있는 단어(브랜치 이름)를 그대로 가져와 자신 있게 틀린다 — 숫자·단어가 조각에 있으니 "근거 있는 답"처럼 보여서 더 위험
- 맞히고 틀린 것과 별개로, 작은 모델은 고유명사를 받아 적다 깨뜨린다(예: 도구 이름이 엉뚱한 철자로)
- 문서 폴더에 없는 지식은 결국 못 다룬다 — 거절하면 다행, 비슷한 조각이 있으면 오답
- 거절 판정을 정확한 문구로만 했다가 3건을 놓쳤다 → 모델은 지시 문구를 조금씩 바꿔 말한다. 채점기도 검증이 필요
