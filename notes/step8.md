# 8단계(추가) 정리 — 4B vs 9B 같은 비교 (2026-11-11)

## 방법

- 같은 계열 큰 모델 `qwen3.5:9b`(7.6GB)로 1단계(문서 없이)·2단계(정답 문서 붙임)·6단계(찾기+답하기, 기존/이름표/이름표+확인 지시)를 같은 질문으로 다시 실행
- 찾기(3~5단계)는 답하는 모델과 상관없어 그대로
- 6단계는 찾기를 먼저 다 끝내고 임베딩 모델을 메모리에서 내린 뒤 9B 로 답하기 (`step6_rag.py`)
- 4B·9B 결과를 같은 거절 판정으로 다시 셈 (`compare_runs.py`). 이유를 길게 붙인 거절("제공된 자료에는 …가 명시되어 있지 않습니다 … 근거 자료가 없습니다")도 거절로 보도록 판정식을 넓힘

## 결과

1·2단계
| | 4B | 9B |
|---|---|---|
| 답 쓰는 속도 | 초당 약 40토큰 | 초당 약 22~25토큰 |
| 문서 없이 회사 질문 | 엉뚱하게 지어냄 | **더 그럴듯하게** 지어냄 (방향이 우연히 비슷, 세부는 지어냄) |
| 정답 문서를 붙였는데 질문과 문서의 말이 다를 때 | 판단 보류 | **이어서 답함** (문서의 "세션 만료"와 질문의 "로그인 풀림"을 연결) |

6단계 (22문항)
| | 4B 기존 | 4B 이름표+확인 지시 | **9B 기존** | 9B 이름표 |
|---|---|---|---|---|
| 위험한 답 (엉뚱한 근거로 자신 있게 틀림) | 2 | 1 | **0** | 0 |
| 잃은 정답 (찾았는데 거절) | 0 | 1 | **0** | 1 |
| 답이 없는 질문 | 다른 프로젝트 문서로 오답 | 오답 | **"이 자료는 다른 프로젝트라 관련 없음"이라며 거절** | 거절 |
| 정답 조각을 근거로 인용 | 14/15 | — | 15/15 | — |
| 문항당 시간 | 7.3초 | 7.2초 | **27.5초** | 24.8초 |

- 9B 이름표+확인 지시 실행은 메모리 부족으로 22문항 중 18문항에서 중단 (그때까지 위험 0)
- 지어낸 숫자는 모두 0
- 4B 에서 보이던 고유명사 깨짐이 9B 에서는 없음

## 메모리

- 16GB Mac 에서 9B(7.6GB)를 돌리면 스왑이 20GB 넘게 차고, 첫 요청은 글자 9개에 160초가 걸리기도 함
- 다른 프로그램이 많이 떠 있으면 실행이 강제 종료됨 → 9B 는 다른 작업이 적을 때만 현실적

## 배운 것

- 4B 가 이름표 + 확인 지시로도 못 고친 "비슷한 다른 대상" 문제를 **9B 는 이름표 없이** 해결했다 — 모델 크기가 가장 큰 차이를 만듦
- 대신 4배 가까이 느리고, 이 Mac 에서는 메모리가 빠듯하다 → 정확도와 속도·자원의 맞바꿈
- 문서 없이 물으면 큰 모델이 **더 그럴듯하게** 틀린다 → 큰 모델일수록 "문서 붙이기 + 모르면 모른다" 지시가 더 중요
- 9B 에는 이름표의 이득이 거의 없고 과잉 거절만 1건 늘었다 → 장치를 더할 때마다 모델별로 다시 재야 함
- 채점기의 거절 판정은 모델마다 말투가 달라 계속 손봐야 했다 — 자동 채점도 검증 대상
